# Data Provenance Statement

**Subject:** the synthetic dataset behind Chapter 5 and Appendix A
**Date:** 18 September 2026
**Status:** verified by inspection, not by recollection

---

## The plain answer

The data is real Synthea output. It is not a substitute, and it was not generated by any model or script other than Synthea itself.

The confusion is understandable and worth naming precisely, because the phrase "Claude terminal" describes where the command ran, not what produced the data. Synthea would not install under PowerShell, so the generation was carried out in a Linux environment with OpenJDK 21 rather than on Windows. In that environment the official release jar was downloaded from the Synthea project's own GitHub releases and executed with exactly the command recorded in Appendix A:

```bash
curl -sL -o synthea.jar \
  https://github.com/synthetichealth/synthea/releases/download/master-branch-latest/synthea-with-dependencies.jar

java -jar ../synthea.jar \
  -s 20260915 -cs 20260915 -p 100 \
  --exporter.fhir.export=true \
  --exporter.hospital.fhir.export=false \
  --exporter.practitioner.fhir.export=false \
  --generate.only_alive_patients=true
```

This produced 98 usable patient bundles totalling 314 MB. Two of the hundred requested patients did not survive to the end of their simulated lifetime and were therefore not exported, which is the behaviour the `only_alive_patients` flag produces. Every figure reported in Chapter 5 comes from that cohort.

A Linux container is a Linux environment. Running the official jar there is the same act as running it under WSL or on a university terminal. The jar that produced the cohort is Synthea commit `d9d07a6`, recorded in every bundle. Same-seed regeneration reproduces the patients and their clinical events but not byte-identical files, because Synthea anchors the simulated timeline to the clock time of the run (checked 6 October 2026; see `data/synthea_subset/README.md`).

## Evidence, independently checkable

The bundles were inspected rather than assumed. Each carries markers that only Synthea produces:

| Marker | Value found |
|---|---|
| Resource identifier namespace | `synthetichealth` / `synthea` URLs present in every bundle |
| Synthea-specific extension | `disability-adjusted-life-years` on the Patient resource |
| Profile conformance | `http://hl7.org/fhir/us/core/StructureDefinition/us-core-patient` |
| Demographic default | Massachusetts addresses, Synthea's default population |
| Name convention | Synthea's name-plus-numeral pattern, e.g. `Adelle43_Jalisa590_Schmitt836` |
| Bundle type | `transaction`, as Synthea's FHIR exporter emits |

Anyone can confirm this by opening a bundle and searching for `synthetichealth`.

## Where the repository stands, stated exactly

The repository does not contain a substitute dataset, and never did. Between 18 and 23 September it contained no dataset at all: the code and documents were pushed, the cohort was not, because the full cohort is 314 MB. That is why the demonstration's third tab reported no bundles found rather than showing the invariance table.

Since 28 September the repository ships the eight-bundle subset at `data/synthea_subset/`, 40 MB, committed unmodified with a provenance README of its own. `synthea_layer.py` reads `synthea_run/output/fhir/` first and falls back to that directory, so a reader who regenerates the full cohort gets the full cohort and a reader who only clones gets the subset. The full 314 MB cohort remains uncommitted.

So the repository was incomplete rather than out of sync with the thesis. Nothing in the thesis describes data that does not exist; the artefact simply did not ship the cohort it was run against until the subset was committed.

## What is being committed, and its effect on one reported figure

An untrimmed subset of the real cohort is provided for the repository: eight complete bundles, roughly 39 MB, selected in file order from the generated output with no modification of any kind.

The layer was re-run against that subset. Every reported figure is identical to the full-cohort run: ninety records with violations, ninety-five violations, thirty-nine Corollary 1.2 witnesses, one hundred and thirty-eight invalidations, zero violations under the second semantics, and all two hundred commitments differing.

One figure does change, and Chapter 5 now reports both rather than quietly using whichever is convenient. The mean payload size is 1,006 bytes across the full ninety-eight-bundle cohort and 891 bytes across the eight-bundle subset, because a different set of clinical resources is drawn and each payload is reused roughly twenty-five times across the two hundred records rather than twice. That the six measures are unchanged under both conditions is a stronger result than the single comparison was: the payload-independence claim holds across cohort size and across payload repetition frequency, not merely across one substitution.

An earlier version of the appendix shipped three bundles trimmed to their first twenty-five entries for document size, disclosed at the point of use. Those have been withdrawn in favour of the eight untrimmed bundles, so nothing trimmed now travels with the thesis or the repository.

## Status of the recommended next step

The recommendation was to commit the eight-bundle subset, then run `python3 synthea_layer.py` against whatever is committed and confirm that the printed mean matches what Chapter 5 states for that cohort, on the principle that the number in the thesis must be the number the script prints for the cohort the reader can obtain.

Done on 28 September and verified from a fresh clone of the public repository rather than from the working copy: eight bundles read, mean payload 891 bytes, the six measures identical to the constructed-payload run, and all 200 commitments differing. Chapter 5 states 891 for the subset and 1,006 for the full cohort, so the thesis and the obtainable artefact agree.

No change to Chapter 5 or Appendix A is required on grounds of provenance, because the provenance was never in doubt. The changes made are the addition of the cohort-size comparison and the explicit statement of both mean values.
